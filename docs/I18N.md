# Internationalisation (English-first)

## Defaults

- **English** is the default language and uses root URLs (`/solutions`, `/quote`, …).
- **Dutch** is available under the `/nl` prefix (`/nl/solutions`, `/nl/quote`, …).
- Pathnames stay English for both locales (expandable later to localised slugs if needed).
- Admin remains English-only at `/admin/*` (no `/nl` prefix).

## Architecture

| Piece | Location |
| --- | --- |
| Locales + path helpers | `src/i18n/config.ts` |
| Dictionaries (UI chrome) | `src/i18n/messages/en.ts`, `nl.ts` |
| Long-form solution copy | `src/i18n/content/solutions.ts` |
| Server dictionary | `src/i18n/get-dictionary.ts` |
| Client provider | `src/i18n/provider.tsx` |
| Locale-aware Link | `src/i18n/locale-link.tsx` |
| Language switcher | `src/i18n/language-switcher.tsx` |
| Middleware (rewrite + legacy redirects) | `src/middleware.ts` |

## Usage

- **Server components:** `const { t, locale } = await getDictionary()`
- **Client components:** `const t = useT()` (requires `I18nProvider` in root layout)
- **Links:** `LocaleLink` / `LocaleLinkButton` so `/nl` prefix is preserved
- Interpolation: `t("about.title", { name: "VDB Digital" })` replaces `{name}`

## Adding a language later

1. Add the locale code to `locales` in `config.ts`.
2. Add `src/i18n/messages/{code}.ts` matching the `Messages` type.
3. Register it in `get-dictionary.ts` catalogs.
4. Translate any content maps under `src/i18n/content/`.
5. Decide prefix strategy (`/de`, …) — keep English paths unless product requires localised slugs.

Do **not** enable a language until the dictionary (and relevant content maps) are complete.

## Legacy redirects (308)

Dutch paths such as `/oplossingen`, `/offerte`, `/winkelwagen` redirect to English equivalents. Prefixed `/nl/oplossingen` also redirects to `/nl/solutions`.
